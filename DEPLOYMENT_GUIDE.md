## 🛠️ Local Development Setup

### 1. Clone and Setup Backend

```bash
cd backend

# Create virtual environment
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Copy environment file
cp ../.env.example .env

# Initialize database (automatic on first run)
# Seed demo data (optional)
python seed/seed_data.py

# Run backend server
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Backend will be available at: `http://localhost:8000`  
API Documentation: `http://localhost:8000/api/docs`

### 2. Setup Frontend

```bash
cd frontend

# Install dependencies
npm install

# Create environment file
echo "VITE_API_URL=http://localhost:8000/api" > .env.local

# Run development server
npm run dev
```

Frontend will be available at: `http://localhost:5173`

## ☁️ Production Deployment

### Option A: Deploy to Render (Recommended for SIH)

#### Step 1: Prepare Backend for Render

1. **Create `render.yaml` in project root:**

```yaml
services:
  - type: web
    name: landsetu-backend
    env: python
    buildCommand: "cd backend && pip install -r requirements.txt"
    startCommand: "cd backend && gunicorn app.main:app -w 4 -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:$PORT"
    envVars:
      - key: PYTHON_VERSION
        value: 3.11.0
      - key: SECRET_KEY
        generateValue: true
      - key: DATABASE_URL
        fromDatabase:
          name: landsetu-db
          property: connectionString
      - key: ALLOWED_ORIGINS
        value: https://landsetu-frontend.onrender.com
databases:
  - name: landsetu-db
    databaseName: landsetu
    user: landsetu_user
```

2. **Update `backend/app/core/config.py` for production:**
   - Ensure DATABASE_URL reads from environment variable (already configured)
   - Set stricter CORS origins

3. **Push to GitHub:**
```bash
git add .
git commit -m "Prepare for Render deployment"
git push origin main
```

4. **Deploy on Render:**
   - Go to https://render.com
   - Click "New +" → "Blueprint"
   - Connect your GitHub repository
   - Select `render.yaml` configuration
   - Click "Apply"

Render will automatically:
- Build the backend
- Create PostgreSQL database
- Set environment variables
- Deploy the service

#### Step 2: Deploy Frontend to Render/Vercel

**For Vercel:**

1. Install Vercel CLI:
```bash
npm install -g vercel
```

2. Deploy:
```bash
cd frontend
vercel login
vercel --prod
```

3. Set environment variable in Vercel dashboard:
   - Go to Project Settings → Environment Variables
   - Add `VITE_API_URL` = `https://your-backend-url.onrender.com/api`

**For Render:**

1. New Web Service
2. Connect GitHub repo
3. Build Command: `cd frontend && npm install && npm run build`
4. Start Command: `npx serve frontend/dist`
5. Add Environment Variable: `VITE_API_URL`

### Option B: Deploy to Railway

#### Backend Deployment:

1. Go to https://railway.app
2. Click "New Project" → "Deploy from GitHub"
3. Select your repository
4. Add variables:
   ```
   SECRET_KEY=<generate-strong-random-key>
   DATABASE_URL=<auto-generated-by-railway>
   ALLOWED_ORIGINS=https://your-frontend-domain.com
   ```
5. Railway auto-detects Python and deploys

#### Frontend Deployment:

1. In same Railway project, click "New" → "Empty Service"
2. Set Build Command: `cd frontend && npm install && npm run build`
3. Set Start Command: `npx serve frontend/dist -p $PORT`
4. Add variable: `VITE_API_URL=https://your-backend.railway.app/api`

### Option C: Docker Deployment (Advanced)

#### Create `Dockerfile` for backend:

```dockerfile
FROM python:3.11-slim

WORKDIR /app

COPY backend/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY backend/ ./

EXPOSE 8000

CMD ["gunicorn", "app.main:app", "-w", "4", "-k", "uvicorn.workers.UvicornWorker", "--bind", "0.0.0.0:8000"]
```

#### Create `Dockerfile` for frontend:

```dockerfile
FROM node:18-alpine AS builder

WORKDIR /app
COPY frontend/package*.json ./
RUN npm ci
COPY frontend/ ./
RUN npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

#### Create `docker-compose.yml`:

```yaml
version: '3.8'

services:
  backend:
    build:
      context: .
      dockerfile: Dockerfile.backend
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://user:pass@db:5432/landsetu
      - SECRET_KEY=${SECRET_KEY}
      - ALLOWED_ORIGINS=http://localhost:3000
    depends_on:
      - db

  frontend:
    build:
      context: .
      dockerfile: Dockerfile.frontend
    ports:
      - "3000:80"
    environment:
      - VITE_API_URL=http://localhost:8000/api

  db:
    image: postgres:15
    volumes:
      - postgres_data:/var/lib/postgresql/data
    environment:
      - POSTGRES_DB=landsetu
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass

volumes:
  postgres_data:
```

Deploy with:
```bash
docker-compose up -d
```

## 📊 Database Migration (SQLite → PostgreSQL)

If moving from SQLite to PostgreSQL for production:

1. **Install PostgreSQL adapter:**
```bash
pip install psycopg2-binary
```

2. **Update DATABASE_URL:**
```bash
DATABASE_URL=postgresql://username:password@hostname:5432/database_name
```

3. **Run migrations:**
Tables will be created automatically on first run.

4. **Seed data:**
```bash
python backend/seed/seed_data.py
```

## 🚨 Common Issues & Solutions

### Issue 1: CORS Errors
**Solution:** Update `ALLOWED_ORIGINS` in backend to include frontend domain exactly (including https://)

### Issue 2: Database Connection Failed
**Solution:** 
- Check DATABASE_URL format
- Ensure database is accessible from hosting provider
- For Render/Railway, use their provided connection string

### Issue 3: Module Not Found (ML Model)
**Solution:**
- Ensure scikit-learn and joblib are in requirements.txt (already added)
- Model is generated on first prediction call if not present

### Issue 4: Frontend Can't Connect to Backend
**Solution:**
- Verify VITE_API_URL is set correctly
- Ensure backend URL uses https:// in production
- Check CORS settings in backend

### Issue 5: Cold Starts on Free Tier
**Solution:**
- Use uptime monitoring service (e.g., UptimeRobot)
- Consider upgrading to paid tier for SIH presentation
